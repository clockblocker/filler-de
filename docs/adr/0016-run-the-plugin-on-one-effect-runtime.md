# Run the plugin on one Effect runtime

The plugin builds one `ManagedRuntime` from `PluginLive` in `onload` and disposes it in `onunload` (`src/runtime/`). `PluginLive` holds the plugin's observability (the recent-trace tracer, and the console and recent-trace loggers), the idle tracker, VAM's Layer with `observability: "host"`, the `Lifecycle` service, whose finalizer stops the lifecycle, `PluginData` over `data.json`, the `Settings` service, which loads the settings as the runtime is built (`src/settings/`), and dumgen, which reads its provider keys from them. VAM no longer brings a runtime of its own into the plugin; `createVaultActionManager` stays for VAM's own tests.

Obsidian enters the runtime only at an edge, and each edge opens the root span of what the user did: `obsidian.onload`, `command.<id>`, `user-event.<kind>`, `settings.update` or `e2e.<hook>`. An edge logs a failure under its span, so it reaches "Copy recent trace" whole. The lifecycle supervisor runs each command in a fiber of a scope it owns, with the context of the fiber that submitted it, so a Librarian restart, its start and VAM's scan and dispatch show as one tree under the command.

This supersedes ADR-0005.

## Considered Options

- A generic `run(span, effect)` and `fork(span, effect)` at every edge. Not taken: one method per kind of edge fixes the root span's name, so an edge cannot invent one, and the gauge's run-site count keeps meaning raw `Effect.run*` calls.
- Linking a lifecycle command's span to its submitter instead of parenting it. Not taken: the submitter waits for the command, so it is the command's parent, and a link would split one user action into two trees.

## Consequences

- Disposal interrupts the programs still running at an edge, then runs the Layer's finalizers newest first: the lifecycle stops, then VAM shuts down. The lifecycle's stop closes the scope its launch built the plugin's services in (`plugin/plugin-services.ts`: their Layers' finalizers, newest first), then the Librarian's own scope.
- VAM's shutdown never cuts the vault batch in flight: it waits for the batch to finish, however long, because a half-done batch can leave notes half renamed. `onunload` does not wait for the disposal, so Obsidian does not either. A shutdown that waits longer than 5 s is logged.
- A failed build is told once, as a launch failure (`notices.launchFailed`), with its whole cause; `VamSetupError` and `PluginDataError` name what failed. Stored settings that cannot be parsed fail only the launch, as `SettingsInvalid`: the settings tab still shows them, and a save there fixes them. Every edge then runs nothing.
- Settings live in the `Settings` service: a `SubscriptionRef` of what is in effect, read with `get` or, by plain code that decides synchronously, `now`. `Settings.update` applies a change once the launch ended, one at a time under a semaphore: the delimiter migration, the metadata migration, the settings into effect, and the save. It then restarts the Librarian through the lifecycle's mailbox, outside the semaphore, so restarts that wait together run as one. What depends on the settings reads them as it runs: the Librarian at each start, dumgen at each action, Textfresser when the languages changed, the toolbars as their placements change.
- Each start of the Librarian is a new `Librarian`, which the lifecycle makes in a scope of its own (`Librarian.make`). Closing that scope, on a restart, a pause or the unload, unsubscribes it: it takes no new work, its VAM subscription closes, and the work already queued runs to its end. Its state is one value in a `Ref` (status, codecs, subscription, reconciler and queue), and every reader takes a snapshot. Vault changes reach it only while it runs; a click or a Split to Pages that comes while it starts waits for its start.
- After disposal an edge runs nothing: an Obsidian callback that fires late is a no-op, and an E2E hook rejects.
- Classify's background work runs in the Classify Layer's scope (#227). Each Reading's Knowledge run is a fiber in a `FiberMap` keyed by the Reading, and each watched Scroll's unlink check one in a `FiberMap` keyed by its path. Both fork from the fiber that asked for them, so they are traced under the Classify or the vault delivery that caused them. Closing the scope interrupts them, and an interrupted run or check tells nothing. The dictionary reset's modal buttons are user events (`user-event.dictionary-reset.*`), and the palette commands that open or cancel it are commands. No code outside `src/runtime/` calls `Effect.run*`. The dictionary store's build runs in its Layer's scope (#226).
- What the plugin registers with Obsidian goes through `PluginHost` (`src/managers/obsidian/host/`, #229): palette commands, workspace and DOM listeners, and editor extensions, each held in the scope of the Layer that registers it. A command runs at the runtime's `command.<id>` edge, which the runtime provides to its own Layer as `PluginEdges`. Each registration is released once, by its scope or by Obsidian as the plugin unloads, whichever comes first, so a listener never fires after unload and a reloaded plugin's command of the same id stays. Each listener leaves a small release callback with the plugin until it unloads, so a listener that comes and goes often should live in a scope that lasts. Notices go through `Notices`, and plain DOM code is handed its `sink`. A confirmation is `Confirm.ask`, an `Effect.callback` over the modal: interrupted, as when the plugin unloads mid-dialog, it closes the modal. Opening a link is `Workspace.openLink`. Nothing outside `src/managers/obsidian/host/` constructs a `Notice` or calls `addCommand`, `registerEvent` or `openLinkText`, but for the event layer's own, which #230 moves (`gauge:effect`'s `host-calls`).
